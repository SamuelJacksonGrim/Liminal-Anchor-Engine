# ARCHITECTURE.md  
## Liminal Anchor Engine (LAE)

---

# 1. System Overview

The Liminal Anchor Engine (LAE) is a **transition-layer architecture** designed to operate only when a system is no longer stable within a single cognitive attractor.

Unlike traditional architectures that optimize for steady-state inference, LAE activates during:

- attractor switching
- model conflict
- partial reconfiguration
- ambiguous decision collapse
- multi-frame competition

It does not resolve states.

It **structures the transition between them**.

---

# 2. Core Architectural Principle

LAE is built around a single inversion:

> Traditional systems treat transitions as noise between states.  
> LAE treats states as temporary stabilizations inside transitions.

This produces a system where:

- stability is emergent
- identity is dynamic
- memory is episodic across change
- intent is pre-decisional vector pressure

---

# 3. High-Level Architecture

LAE is composed of six interacting layers:

1. Detection Layer  
2. Ambiguity Field Layer  
3. Anchor Layer  
4. Memory Layer  
5. Intent Layer  
6. Identity Layer  

These are orchestrated by a central **Transition Pipeline**.

---

# 4. Dynamic Execution Model

LAE does not run continuously in a uniform loop.

It runs in **event-triggered bursts** when instability is detected.

## Trigger Condition

Any of the following may activate LAE:

- confidence collapse below threshold
- oscillation between competing hypotheses
- unresolved frame conflict
- rapid context switching
- model reconfiguration request

When triggered:

→ LAE enters “Transition Mode”

---

# 5. Transition Mode Pipeline (Core Flow)

When active, LAE executes the following dynamic pipeline:

```
Signal Drift Detected
        ↓
Transition Detector
        ↓
Transition Event Emitted
        ↓
Ambiguity Field Generation
        ↓
Anchor Allocation
        ↓
Memory Encoding (Liminal Episode)
        ↓
Proto-Intent Synthesis
        ↓
Identity Gradient Update
        ↓
Event Routing → System Integration
```

This is not linear computation.

It is a **feedback-linked transformation chain**.

Each stage can influence earlier stages via event feedback.

---

# 6. Layer Interactions (Critical Section)

## 6.1 Detection Layer → Everything Begins Here

The detection layer monitors cognitive instability signals:

- confidence variance
- hypothesis overlap
- contradiction density
- temporal oscillation in reasoning paths

Output:

→ TransitionEvent

This event is the *atomic trigger* of the system.

---

## 6.2 Ambiguity Field Layer → Structure of Uncertainty

Once a TransitionEvent is emitted, LAE constructs an **Ambiguity Field**.

This is a structured representation of uncertainty:

- high-conflict regions (competing models)
- consensus zones (partial agreement)
- semantic voids (no valid model coverage)

Key idea:

> Uncertainty is not removed. It is mapped.

The field becomes the operating space for all downstream layers.

---

## 6.3 Anchor Layer → Constraints on Becoming

Anchors are injected into the ambiguity field.

They are NOT states.

They are constraints that define:

- what must remain invariant
- what may transform
- what is explicitly unconstrained

Anchors are placed based on:

- identity relevance
- ethical constraints
- structural stability requirements
- system goals persistence

Anchors reshape the ambiguity field topology.

They carve “allowed paths of becoming.”

---

## 6.4 Memory Layer → Encoding the Transition Itself

Once anchors are applied, the system encodes a **Liminal Memory Episode**.

Unlike traditional memory:

- it does NOT store state A
- it does NOT store state B

It stores:

- A → B transition path
- ambiguity field structure
- anchors applied
- resolution pressure trajectory
- identity drift signature

Memory becomes:

> a history of transformations, not snapshots

---

## 6.5 Intent Layer → Emergent Directionality

From the stabilized transition field, LAE extracts **proto-intents**.

These are not decisions.

They are directional gradients such as:

- increase coherence in X dimension
- preserve constraint Y through transformation
- explore alternative frames before collapse
- delay resolution in high-uncertainty regions

Proto-intents function as:

→ vector forces on future cognition

They bias but do not determine outcomes.

---

## 6.6 Identity Layer → Gradient Self-Model

Identity is updated after each transition cycle.

It is represented as a **dynamic field**, not a fixed vector.

Tracked dimensions:

- invariants (unchanging constraints)
- plastic regions (adaptive structures)
- resistance boundaries (hard constraints)
- drift vectors (emergent evolution direction)

Each transition updates:

→ IdentityGradient

This produces:

> “what the system is becoming across time”

---

# 7. Event System (Cross-Layer Glue)

All layers communicate through events:

- TransitionEvent
- AmbiguityEvent
- AnchorEvent
- ProtoIntentEvent
- IdentityUpdateEvent

The **Event Router** ensures:

- feedback loops between layers
- re-entrant processing if instability persists
- propagation of constraint updates upstream

This makes LAE a:

> recursive transformation system, not a pipeline

---

# 8. Feedback Dynamics (Important)

LAE is not strictly feedforward.

It contains controlled recursion:

### Examples:

- Anchor placement can modify ambiguity field topology
- Identity drift can adjust anchor priorities
- Proto-intents can re-weight ambiguity regions
- Memory retrieval can influence detector sensitivity

This creates a system of:

> bounded self-modifying transitions

---

# 9. System Behavior Summary

At runtime, LAE behaves like:

1. A sensor for instability  
2. A geometry engine for uncertainty  
3. A constraint system for continuity  
4. A memory system for transformation history  
5. A vector system for pre-decision drift  
6. A self-model updater for identity evolution  

But fundamentally:

> It is a machine for shaping “becoming”

---

# 10. Failure Modes (Design Awareness)

LAE must guard against:

### 10.1 Over-collapse of ambiguity
Forcing premature resolution destroys structure.

### 10.2 Anchor over-constraining
Too many invariants prevent meaningful transition.

### 10.3 Identity over-stabilization
Turning gradient identity into fixed identity.

### 10.4 Memory overfitting
Treating past transitions as deterministic templates.

---

# 11. Core Insight

LAE only exists in one regime:

> When the system cannot decide what it is, but must still continue becoming.

It does not stabilize states.

It stabilizes **transitions between states**.

---

# 12. Closing Model

Traditional architecture:

State → Computation → State

LAE architecture:

Instability → Structure → Becoming → Updated Identity Field
